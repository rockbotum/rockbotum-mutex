# AGENTS.md

## О проекте

Репозиторий с различными реализациями мьютексов в Go для изучения и сравнения подходов к синхронизации.

## Цель

- Исследовать разные подходы к реализации мьютексов (spin lock, CAS, condition variables, etc.)
- Сравнить производительность и поведение в разных сценариях
- Понять внутреннее устройство `sync.Mutex` в Go

## Правила для AI-агентов

### 1. Перед изменениями

- **Всегда читай существующий код** перед модификацией.
- **Проверяй, нет ли уже похожей реализации** в репозитории.
- **Не удаляй существующие тесты** — только добавляй новые.

### 2. Код

- **Форматируй код** через `go fmt ./...`.
- **Запускай `go vet ./...`** перед коммитом.
- **Добавляй тесты** для новых реализаций.
- **Используй понятные имена** переменных и функций.
- **Комментируй сложные места** (почему так, а не иначе).

### 3. Тесты

- **Минимум 3 теста** на новую реализацию:
  - `TestBasicLockUnlock` — базовая функциональность.
  - `TestConcurrentAccess` — конкурентный доступ.
  - `TestStress` — стресс-тест с множеством горутин.
- **Запускай все тесты** перед пушем: `go test ./... -race`.

### 4. Бенчмарки

- **Добавляй бенчмарки** для новых реализаций.
- **Сравнивай с `sync.Mutex`** — это baseline.
- **Запускай бенчмарки** перед коммитом: `go test ./benchmark -bench=. -benchmem`.

### 5. Git

- **Коммить атомарно** — одно изменение = один коммит.
- **Пиши понятные сообщения**:
  - ✅ `Add spin lock implementation with CAS`
  - ❌ `update code`
- **Пуш только после успешных тестов**.

### 6. Документация

- **Обновляй README.md** при добавлении новой реализации.
- **Добавляй примеры использования** в `examples/`.
- **Описывай trade-offs** (когда использовать, когда нет).

## Чек-лист перед пушем

- [ ] `go fmt ./...` — код отформатирован.
- [ ] `go vet ./...` — нет предупреждений.
- [ ] `go test ./... -race` — все тесты проходят.
- [ ] `go test ./benchmark -bench=. -benchmem` — бенчмарки работают.
- [ ] README.md обновлён (если добавлена новая реализация).
- [ ] Коммиты атомарные с понятными сообщениями.

## Пример workflow

```bash
# 1. Создать новую реализацию
mkdir -p cas
vim cas/cas_mutex.go

# 2. Добавить тесты
vim cas/cas_mutex_test.go

# 3. Отформатировать
go fmt ./...

# 4. Проверить
go vet ./...
go test ./... -race

# 5. Запустить бенчмарки
go test ./benchmark -bench=. -benchmem

# 6. Закоммитить
git add cas/
git commit -m "Add CAS-based mutex implementation"

# 7. Запушить
git push
```
